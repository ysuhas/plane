# Scholrithm brand layer

This fork is Plane (AGPL-3.0) plus a thin brand layer. `preview` mirrors upstream and never carries our changes; `brand` is `preview` plus the files below.

## What the brand layer touches

| Change                    | Files                                                                                          | Upstream conflict risk              |
| ------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------- |
| Logo component            | `packages/blocks/src/icons/brand/plane-logo.tsx` (export name kept)                            | low: one upstream edit in 9 months  |
| Brand colour              | `packages/tailwind-config/brand.css` (new) + one import line in `index.css`                    | low                                 |
| Icons, spinners, OG image | binary files under `apps/*/app/assets`, `apps/*/public`, regenerated by `generate-assets.py`   | none: upstream has not touched them |
| Local dev ports           | `docker-compose-local.ports.yml` (new); `docker-compose-local.yml` stays identical to upstream | none                                |

Everything else is new files that upstream does not have, so they cannot conflict.

## Pulling upstream

```sh
git fetch upstream
git switch preview && git merge --ff-only upstream/preview
git switch brand && git merge preview
pnpm install
pnpm turbo run build --filter=@plane/blocks   # @plane/blocks serves the logo from dist/
python3 branding/check.py                     # did upstream break or undo the rebrand?
```

`check.py` prints what to fix. Typical causes:

- **PlaneLogo was overwritten**: re-apply the mark from `branding/scholrithm-mark.svg`.
- **propel renamed a `--brand-*` token or its dark-mode selector**: update `brand.css`.
- **An asset moved**: `generate-assets.py` stops with the missing path; update the path there and re-run it.
- **A merge conflict on a binary asset**: take either side, then run `python3 branding/generate-assets.py`.

## Change the brand

- Colour: the two hex values at the top of `brand.css` (light and dark mode).
- Logo: replace `scholrithm-mark.svg`, paste the same paths into `plane-logo.tsx`, then run `python3 branding/generate-assets.py` (needs macOS `sips` and Pillow).

## Local dev ports

Plane's defaults collide with other local stacks (redis 6379, api 8000). Start the stack with the override file:

```sh
docker compose -f docker-compose-local.yml -f docker-compose-local.ports.yml up -d
```

Defaults: redis 6380, api 8002 (db 5432 and minio 9000/9090 unchanged). Move any of them per machine with `LOCAL_REDIS_PORT`, `LOCAL_API_PORT`, `LOCAL_DB_PORT`, `LOCAL_MINIO_PORT`, `LOCAL_MINIO_CONSOLE_PORT` in the root `.env`.

After `./setup.sh`, point the apps at the api port in `apps/{web,admin,space}/.env` (`VITE_API_BASE_URL`) and `apps/live/.env` (`API_BASE_URL`, `REDIS_URL`), for example `http://localhost:8002`. The `.env` files are git-ignored, so this is a one-time step per clone.

## Deploying

The root `docker-compose.yml` builds every service from this source, so it ships the branded UI. `deployments/cli/community` pulls prebuilt `makeplane/*` images and would show stock Plane.

## Not branded yet

Product name in page titles, manifests and i18n strings; the `PlaneLockup` wordmark; the Plane illustrations on the instance-not-ready screens.
