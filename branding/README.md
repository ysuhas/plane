# Scholrithm brand layer

This fork is Plane (AGPL-3.0) plus a thin brand layer. `preview` mirrors upstream and never carries our changes; `brand` is `preview` plus the files below.

## What the brand layer touches

| Change                    | Files                                                                                                                                           | Upstream conflict risk                                                                       |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Logo and lockup           | `plane-logo.tsx`, `plane-lockup.tsx` in `packages/blocks/src/icons/brand/` (export names kept), `apps/admin/components/common/plane-lockup.tsx` | low: one upstream edit in 9 months                                                           |
| Product name text         | ~380 files rewritten by `rename.py`: locale JSON values (all 22 locales) and UI strings in web, admin, space, `constants/metadata.ts`           | medium: conflicts only where upstream edits the same line, and `rename.py` regenerates those |
| Brand colour              | `packages/tailwind-config/brand.css` (new) + one import line in `index.css`                                                                     | low                                                                                          |
| Icons, spinners, OG image | binary files under `apps/*/app/assets`, `apps/*/public`, regenerated by `generate-assets.py`                                                    | none: upstream has not touched them                                                          |
| Local dev ports           | `docker-compose-local.ports.yml` (new); `docker-compose-local.yml` stays identical to upstream                                                  | none                                                                                         |

Everything else is new files that upstream does not have, so they cannot conflict.

## Pulling upstream

```sh
git fetch upstream
git switch preview && git merge --ff-only upstream/preview
git switch brand && git merge preview
pnpm install
python3 branding/rename.py                    # new upstream strings say "Plane"; this renames them
pnpm turbo run build --filter=@plane/blocks   # @plane/blocks serves the logo from dist/
python3 branding/check.py                     # did upstream break or undo the rebrand?
```

If the merge conflicts only in files `rename.py` rewrites (locale JSON, UI strings), don't hand-merge: `git checkout --theirs <files>`, run `python3 branding/rename.py`, then format and commit. The pre-commit hook runs `oxlint --deny-warnings` and some files `rename.py` rewrites already carry upstream lint warnings (31 at the time of writing, identical before and after the rename), so that commit needs `--no-verify`. Do the hook's other job by hand first: `pnpm exec oxfmt $(git diff --name-only)` re-wraps lines the longer name pushed past the print width.

`check.py` prints what to fix. Typical causes:

- **Upstream added strings that say "Plane"**: `python3 branding/rename.py`.
- **PlaneLogo or PlaneLockup was overwritten**: re-apply the mark from `branding/scholrithm-mark.svg` (the lockup is the mark plus the SCHOLRITHM wordmark text).
- **propel renamed a `--brand-*` token or its dark-mode selector**: update `brand.css`.
- **An asset moved**: `generate-assets.py` stops with the missing path; update the path there and re-run it.
- **A merge conflict on a binary asset**: take either side, then run `python3 branding/generate-assets.py`.

## Change the brand

- Colour: the two hex values at the top of `brand.css` (light and dark mode).
- Logo: replace `scholrithm-mark.svg`, paste the same paths into `plane-logo.tsx`, then run `python3 branding/generate-assets.py` (needs macOS `sips` and Pillow).

## Local dev ports

Plane's defaults collide with other local stacks (redis 6379, api 8000). Start the stack with the override file:

```sh
docker compose -f docker-compose-local.yml -f docker-compose-local.ports.yml up -d
```

Defaults: redis 6380, api 8002 (db 5432 and minio 9000/9090 unchanged). Move any of them per machine with `LOCAL_REDIS_PORT`, `LOCAL_API_PORT`, `LOCAL_DB_PORT`, `LOCAL_MINIO_PORT`, `LOCAL_MINIO_CONSOLE_PORT` in the root `.env`.

After `./setup.sh`, point the apps at the api port in `apps/{web,admin,space}/.env` (`VITE_API_BASE_URL`) and `apps/live/.env` (`API_BASE_URL`, `REDIS_URL`), for example `http://localhost:8002`. The `.env` files are git-ignored, so this is a one-time step per clone.

## Deploying

The root `docker-compose.yml` builds every service from this source, so it ships the branded UI. `deployments/cli/community` pulls prebuilt `makeplane/*` images and would show stock Plane.

## Kept as "Plane" on purpose

`rename.py` leaves strings that describe the upstream vendor, not this product. The patterns are the `KEEP` list at the top of the script.

- **Telemetry consent** (admin general settings and instance setup): the labels say Plane collects the usage data, so renaming them would misstate who receives it. Telemetry is the per-instance `is_telemetry_enabled` setting; decide whether to leave it on.
- **Plane's own docs, changelog and marketing**: "Open Plane documentation", "New at Plane", "Discover why teams switch to Plane", "Powered by Plane Pages", "Join 10,000+ teams building with Plane", and the manifest line claiming Plane's results.
- **Commercial plans**: everything under `billing/` and `license/`, `constants/payment.ts`, and any "Plane Pro/Business/Enterprise/One/Cloud" text.
- **The pun** in the Space error page ("That crashed Plane, pun intended").

## Not branded yet

The Plane illustrations (instance-not-ready screens, maintenance page, `plane-takeoff.png`), the backend (email templates, API error text, the `plane.so` links), and the tagline, which still reads "Simple, extensible, open-source project management tool".
